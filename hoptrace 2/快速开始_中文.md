# HopTrace Android 快速开始

## 项目定位

HopTrace 是原生 Android 网络诊断 App，使用 ICMP Echo + TTL/Hop Limit 逐跳探测，支持 IPv4、IPv6 与 Auto；将公网路由跳点交给 IPinfo City-level API 查询城市级估算坐标，并使用 MapLibre Native + OpenFreeMap 绘制地图和跳点连线。

## Android 版本

- `minSdk 26`：Android 8.0+
- `compileSdk 37` / `targetSdk 37`：面向 Android 17，同时覆盖 Android 15、16
- Java 17、NDK `28.2.13676358`、CMake `3.22.1`

## 地理位置 API

应用使用 `https://ipinfo.io/{IP}/json?token=...` 的 IPinfo City-level / Legacy Free 接口，以取得 `city`、`region`、`country`、`org` 和 `loc` 经纬度。

首次运行后，点击右上角 **IPinfo API**，粘贴你自己的 Token。应用不会内置共享 Token。每个公网 IP 的结果本地缓存 7 天；同一个 IP 在多跳中重复出现时会复用同一份查询结果。私网、回环、链路本地、组播及文档保留地址不会发送到 IPinfo。

注意：IPinfo Lite 虽然不限请求次数，但免费数据主要是国家/ASN 维度，没有城市坐标；不能满足本 App 的城市级地图需求。IPinfo 官方资料当前列出的 Legacy Free 城市级 API 配额为每月 50,000 次。服务计划可能变更，请以账户 Dashboard 为准。

## 地图

MapLibre Native OpenGL SDK 读取 OpenFreeMap Liberty 样式。公共地图服务当前公布无需 API Key、无地图浏览/请求次数限制；它是公共服务，不等同于有 SLA 的商业地图 API。

## 编译 APK

安装 Android Studio，并通过 SDK Manager 安装：

- Android SDK Platform 37
- Android SDK Build Tools 36.0.0
- Android NDK 28.2.13676358
- CMake 3.22.1

在项目根目录执行：

```bash
./gradlew assembleDebug
```

APK 路径：

```text
app/build/outputs/apk/debug/app-debug.apk
```

首次构建需要联网下载 Gradle、Android Gradle Plugin、AndroidX、Material Components 和 MapLibre 依赖。

## ICMP 的限制

底层采用 Linux ping socket（`SOCK_DGRAM` + `IP_RECVERR` / `IPV6_RECVERR`）和 error queue，不请求 Root 权限。但不同厂商系统内核可能禁用普通应用的 ping socket，运营商/防火墙也可能过滤 ICMP；因此不能保证每一台 ROM 都可用。Traceroute 中的 `*` 超时也可能是路由器不回应或限速，不代表链路一定中断。

## 位置精度说明

地图显示的是 IP 注册信息/商业数据库估算的城市或网络区域中心点，不是路由器的 GPS 坐标，也不保证每跳位置都准确。有些骨干网、Anycast、VPN、运营商 NAT 或云网络 IP 可能显示为运营商登记地，与设备实际所在地相差很远。

## 使用 GitHub Actions 云端构建和 Android 模拟器运行测试

项目附带 `.github/workflows/build-apk.yml`。这条工作流不仅执行 Gradle 编译，还会启动 Android 模拟器做运行时测试；只有所有测试通过后才会发布 APK。

1. 在 GitHub 创建一个新仓库，建议设为 **Private**。
2. 解压本项目 ZIP，进入 `hoptrace` 文件夹。
3. 将 `hoptrace` 文件夹内的所有文件和目录上传到仓库根目录。仓库根目录必须直接看到 `settings.gradle`、`build.gradle`、`app/`、`gradle/` 和 `.github/`；不要把整个 `hoptrace/` 再套在仓库里面。
4. 打开仓库的 **Actions** 页面，选择 **HopTrace - build, device-test, and package APK**，点击 **Run workflow**。
5. 工作流会依次在 Android API 35、36、37 的云端 Android 模拟器运行 instrumentation tests。测试包括：主界面启动、IPinfo 设置窗口、MapLibre 样式加载、IPv4/IPv6 ICMP loopback，以及公网/私网 IP 过滤。
6. 只有三个 Android API 的测试全通过、APK 签名和原生库检查通过后，工作流才会发布最终 APK。
7. 在该次成功运行页面的 **Artifacts** 区域下载 `HopTrace-1.1.1-debug.apk`。新版使用 GitHub Actions upload-artifact v7 的单文件直传模式（`archive: false`），下载得到的就是 APK 文件，不需要再解压 ZIP。

云端工具链固定为 JDK 17、Android SDK API 37、Build Tools 36.0.0、NDK 28.2.13676358、CMake 3.22.1 和 Gradle 9.6.0。项目没有 `gradle-wrapper.jar`，因此工作流下载固定版本的 Gradle 并直接执行 `gradle`，不调用 `./gradlew`。

### Firebase 日志对应的启动崩溃修复

你提供的完整 Firebase Logcat 只有一条 HopTrace 致命异常：`MainActivity.buildScreen()` 将普通 `ViewGroup.LayoutParams` 传给 `TextInputLayout.addView()`，而 Material `TextInputLayout` 内部需要 `LinearLayout.LayoutParams`，因此启动阶段发生 `ClassCastException`。同一种错误还存在于 IPinfo Token 对话框。本版本的两个输入框都已修复；工作流也会在编译前验证源码。之前 Robo 日志里的 `LaunchFailedException` 是主进程崩溃后的结果，不是另一处独立崩溃。

### 安装提示

如果安装新版 APK 时 Android 报签名不一致，请先卸载之前安装的 HopTrace，再安装新版。GitHub 云端 Runner 每次运行都会生成临时 Debug 签名密钥，旧 APK 和新 APK 可能不是同一签名。

## 验收边界

工作流的 Android 模拟器测试通过后，能证明 APK 至少通过 Android 15/16/17 对应 API 35/36/37 的启动、设置窗口、地图样式和 IPv4/IPv6 loopback ICMP 测试。它不能保证每一家手机厂商、运营商或 VPN 都允许完整的 ICMP traceroute；某些网络会过滤或限速 ICMP。IP 地理位置必须由用户自行提供 IPinfo City-level Token，坐标是数据库估算位置，不是路由器 GPS 实测位置。
