# HopTrace Android 1.2.0 快速开始

## 本次升级内容

以已经通过 Firebase 启动验证的 IPinfo 版本为基线，保留原 IPinfo City-level Token、地理字段、7 天缓存、ICMP 原生路径和 MapLibre/OpenFreeMap 底图。新增功能如下：

1. **可选自定义 DNS：** 默认仍使用 Android 系统 DNS。切换到 Custom DNS 后，可填写数字 IPv4 或 IPv6 DNS 服务器地址，端口固定为 53。IPv4 模式查询 A，IPv6 模式查询 AAAA，Auto 优先 A、无 IPv4 答案时再尝试 AAAA。DNS 响应被截断时回退到 TCP。
2. **Traceroute 模式切换：** 可选择 ICMP 或 UDP。UDP 使用目标端口 33434 起始的探测端口序列，通过 Linux error queue 读取 TTL Exceeded 和目标端口不可达响应。原有 ICMP 接收路径保持原样。
3. **地图轨迹升级：** 轨迹使用白色描边与蓝色分段线，单独显示每跳 POP 标记和 hop 序号；跨国家段使用橙色高亮；每个首次出现的国家在其第一个已定位 POP 旁标注国家名称和 POP IP。点击点位/国家标签可看详情；点击 Full screen 可全屏交互查看。

IP 地理定位仍使用你此前配置成功的 IPinfo City-level API。**不需要换 API，也不需要重新申请 Token。**

## IPinfo Token

首次使用时，点击主界面右上角 **IPinfo API**，填入你自己的 City-level Token 并保存。Token 只保存在 App 私有设置中，没有写入源码或 APK。公共 hop IP 才会提交查询；私网、CGNAT、链路本地、回环、组播和文档保留地址不会查询。结果本地缓存 7 天。

## 自定义 DNS 怎么用

- 保持 **System default**：继续使用 Android 当前网络配置的默认 DNS。
- 选择 **Custom DNS**：填入 DNS 服务器 IP，例如 `1.1.1.1`、`8.8.8.8` 或 `2606:4700:4700::1111`。
- DNS 服务器输入框只接受数字 IPv4/IPv6 地址，不接受 `dns.google` 这类主机名或 URL；否则解析 DNS 服务器本身又会依赖系统 DNS。
- 可用 IPv4 DNS 服务器查询 AAAA，也可用 IPv6 DNS 服务器查询 A；最终选哪个目标地址由上方 Auto/IPv4/IPv6 选项决定。
- 自定义 DNS 需要当前网络允许设备直接访问指定 resolver 的 UDP/TCP 53 端口。部分网络会拦截外部 DNS。

## UDP Traceroute 注意事项

UDP 模式向 `33434 + hop/probe` 端口发送 UDP 包，根据路由器返回的 ICMP Time Exceeded 识别中间跳点；目标返回 Port Unreachable 时视为到达目标。部分路由器、VPN、运营商或防火墙会屏蔽 UDP 或相关 ICMP 错误报文，出现 `*` 或无法到达不一定代表路由中断。ICMP 模式仍保留原来的实现。

### 上传源码

1. 解压源码 ZIP，进入 `hoptrace` 项目目录。
2. 将目录内全部文件上传到 GitHub 仓库根目录。仓库根目录应直接看到 `settings.gradle`、`build.gradle`、`app/`、`gradle/` 和 `.github/`。
3. macOS Finder 默认隐藏 `.github`；按 `Command + Shift + .` 显示隐藏文件。网页端若提示 `This file is hidden`，可在 GitHub 网页选择 **Add file → Create new file**，文件路径输入 `.github/workflows/build-apk.yml`，再粘贴工作流内容；也可以使用 GitHub Desktop 推送整个目录。
4. 进入 **Actions → HopTrace - build APK only → Run workflow**。
5. 构建成功后，在该次运行底部 Artifacts 下载 `HopTrace-1.2.0-debug.apk`。本工作流使用 `archive: false`，下载得到的是 APK 本身，不是 ZIP。

工作流会检查源码文件、Gradle 依赖仓库、APK 签名、ZIP 对齐、包名、SDK 版本和三种 ABI 的原生库。**它只证明 APK 构建与打包检查通过，不会声称应用已经运行通过。** 如需云端真机/模拟器运行测试，请把生成的 APK 上传 Firebase Test Lab。Firebase Test Lab 负责测试 APK，不负责从源码编译 APK。

## 当前源码验证边界

当前制作环境没有 Android SDK/NDK，不能在这里执行完整 Android Gradle 构建或真机安装。已完成的本机验证：严格警告模式下编译 C++ JNI 源码；UDP IPv4/IPv6 回环 traceroute；自定义 DNS A/AAAA 报文解析；通过本地 DNS 测试服务器真实执行 IPv4/IPv6 A/AAAA 查询；以及 XML/YAML/Shell/源码预检和 ZIP 完整性检查。本机容器策略禁止创建 ICMP ping socket，因此无法在这个 Linux 容器中实测 ICMP；原有 ICMP 接收函数保持原版不动。仍需用 GitHub Actions 构建 APK，再通过 Firebase Test Lab 验证完整 Android 运行行为。


### 自定义 DNS 的地址选择说明

- System default：使用 Android 当前网络配置的系统 DNS。
- Custom DNS：直接向你填写的数字 IPv4 或 IPv6 DNS 地址发送 DNS 请求，端口固定为 53。
- IPv4 模式查询 A 记录；IPv6 模式查询 AAAA 记录。Auto 模式先尝试 A，若无结果再尝试 AAAA。
- 对 UDP 响应被截断的 DNS 消息，会自动回退到 TCP/53。
- 输入目标本身是 IP 地址时，不会执行 DNS 查询。

### 地图说明

地图只绘制 IPinfo 返回有效经纬度的公网 hop。点代表 POP 位置估算，蓝色线段连接已定位的相邻 POP，橙色线段表示数据库返回的国家发生变化。每个首次出现的国家会显示国家名称和对应 POP IP。点击点或国家标签查看 hop 详情；使用 Full screen 打开全屏地图。

地图位置是 IP 数据库估算值，不是路由器 GPS；连线是已定位 POP 之间的示意线，不代表已验证的光纤实际走向。
